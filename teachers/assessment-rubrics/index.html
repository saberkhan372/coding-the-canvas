Assessment & Rubrics

Three performance levels — reproduce, modify, extend — that scale from concept exercises to full project checkpoints.

Portfolio template Lesson plan template

The core rubric framework

Reproduce · Modify · Extend

Every CS Canvas lesson can be assessed on three levels. Reproduce shows comprehension. Modify shows understanding. Extend shows transfer. The canvas output is always the first piece of evidence — does it do what the student claims?

  • Reproduce: student runs the example and explains what each line does
  • Modify: student changes values, layout, or logic with intention
  • Extend: student adds a new idea that requires understanding the concept
  • Evidence: canvas screenshot + relevant code excerpt + written reflection

Concept rubric — for single-lesson checkpoints

Level Code & output Explanation Iteration
3 · Extend Sketch runs and adds a new behavior or visual element not in the original example. Code is purposeful — student can justify every addition. Student explains the concept in their own words and describes how their extension uses it. Shows at least one deliberate revision: a bug found and fixed, or a design choice changed with a reason.
2 · Modify Sketch runs. Student changed at least two values, names, or logic branches with a clear intention (not random trial and error). Student can point to the key line(s) and describe what changes when they are altered. Shows evidence of trying something that didn't work, even if unexplained.
1 · Reproduce Sketch runs using the provided example code. Output matches the expected canvas result. Student can read the code aloud and give a surface-level description of what it does. Little or no revision visible.
0 · Not yet Sketch does not run, or output is unrelated to the concept. Student cannot explain any part of the code. —

Section checkpoints — end-of-section project prompts

§1–§2 Animated scene

Build a scene with at least 5 shapes that includes one moving element. Explain how position is calculated each frame.

coordinates draw loop variables
§3 Interactive toy

Build a sketch that responds to the mouse in at least two distinct ways. At least one must use an if/else branch.

events conditionals booleans
§4 Particle system

An array of at least 20 objects (class with 3+ properties, 2+ methods). Click to add. Optionally: menu and game-over screens.

classes arrays state
§5 Data portrait

Load an image or dataset and generate a visual that reveals something. Explain what the data shows and what was lost or changed.

pixel arrays data loading visualization
§6 Critical filter

Apply a filter or transformation and write a short analysis: who does it help, who might it harm, and what was your design intention?

bias accessibility reflection
§7 Recursive fractal or swarm

Either a recursive fractal (trace the base case) or an ArrayList-driven particle swarm where items join and leave dynamically.

recursion ArrayList dynamic lists

Portfolio evidence

For each checkpoint, collect: a canvas screenshot, the relevant code excerpt (not the whole file), a 2–3 sentence student reflection explaining one decision, and an optional next-step idea.

See the portfolio template for the student-facing version.

AP CSP alignment

The §4 checkpoint (particle system) maps directly to Create Performance Task requirements: a list (array), a procedure with a parameter (class method), and an iteration statement (for loop). Students can use their checkpoint sketch as a CPT starting point.

AP CS A alignment

The §4 and §7 checkpoints generate authentic FRQ situations: writing a class with fields and methods, traversing an array, and manipulating an ArrayList. Add a "trace this code" question to any checkpoint to practice FRQ reasoning.
