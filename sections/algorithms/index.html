What this section covers

The final section reaches for two of the most visually powerful ideas in CS: recursion and dynamic collections. Recursion is taught through fractals — students see the call stack become a branching tree on screen. ArrayList is taught through a particle system — objects that spawn, move, and die in real time. Both concepts are AP CSA exam targets.

  • Recursion: base case and recursive case as a drawing rule
  • The call stack shown as nested visual structure
  • ArrayList: adding/removing objects while iterating
  • Particle system as a capstone project frame
  • AP CSA FRQ patterns in both concepts

Recursion (CON-2) and ArrayList (ARR-3) appear in the AP CSA free-response section every year. The fractal and particle demos give students a visual mental model to draw on during the exam.

Teacher framing

On recursion: Students often freeze on the "stack overflow" mental model before they have an intuition for the base case. Start with the visual — draw the tree first, then trace the code backward. Let the picture teach the concept.

On ArrayList: The key moment is realizing you can't use a regular for loop to remove items while iterating. Show the off-by-one bug live, then introduce the backwards loop or iterator pattern.

Learner framing

Recursion is just a function that calls itself — with a safety exit. Every branch of a fractal tree is drawn by the same rule applied at smaller and smaller scales.

ArrayList lets your sketch have a crowd — a list of objects that can grow when something is born and shrink when something dies, all managed automatically.

Common misconceptions

  • Recursion without a base case → stack overflow
  • The base case is what stops the recursion, not what starts it
  • Can't remove from an ArrayList while iterating forward
  • ArrayList index shifts after removal — backwards loop avoids this
