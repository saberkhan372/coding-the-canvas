Make It Respond

Mouse input, keyboard events, booleans, and the moment a sketch stops running and starts listening.

Start Concept 04 Open Playground

Concepts 04 – 05  ·  Interaction & logic

What this section covers

A sketch that responds to the user feels alive in a way that pure animation doesn't. Students learn to read mouseX/mouseY, detect clicks and key presses, and then branch: "if the user is over here, do this — otherwise do that." Boolean logic arrives through the canvas, not through abstract truth tables.

  • mouseX, mouseY as live variables
  • mousePressed, keyPressed event functions
  • Boolean values: true / false as the two states of the world
  • if / else branching tied to visible outcomes
  • Hit detection: is the pointer inside a shape?

Teacher framing

Key demo: Draw a circle that follows the mouse before introducing any boolean. Then ask: "what would happen if the circle turned red only when mouseX is past center?" That natural question motivates if without a lecture.

Checkpoint: Students build a sketch where clicking toggles between two visual states (e.g. day/night, open/closed), using a boolean variable to track state.

Learner framing

Your sketch can now ask questions. "Is the mouse on the left side?" is a yes/no question — and yes/no is exactly what true and false mean in code.

Every interactive thing you've ever used — games, apps, websites — is built from millions of these tiny questions running every second.

Common misconceptions

  • mousePressed (variable) vs mousePressed() (function) differ
  • if/else if/else only one branch runs per frame
  • Boolean variables should be named as yes/no questions
  • Hit detection needs all four boundary checks
