What this section covers

This is the longest and most consequential section — five concepts that together constitute the heart of programming. Loops eliminate repetition. Functions create reusable verbs. Arrays hold collections. Objects bundle data with behavior. State machines let a sketch have modes. Each concept builds directly on the last.

  • For loops with visual output (grids, patterns)
  • Functions as named, reusable drawing operations
  • Arrays as ordered lists of values or objects
  • Objects: grouping data and methods together
  • State machines: screens, modes, game phases

This section covers more AP CS A Units (1–5) than any other. Loops (CON), methods (MOD), and arrays (ARR) are tested directly in the AP CSA exam FRQs.

Teacher framing

Arc advice: Spend at least 2 periods on loops before introducing functions. The grid-making power of a nested for loop is motivating on its own — don't rush to abstraction.

Milestone project: A particle system (array of objects, each with draw/update methods) is the natural capstone for this section and directly previews AP CSA FRQ style.

Learner framing

A loop draws 100 dots in 3 lines instead of 300. A function lets you say "draw a flower here" without repeating 20 lines. An object is just a dot that knows its own position and how to move itself.

By the end of this section you can build a game with a title screen, a play screen, and a game-over screen — all in one sketch.

Common misconceptions

  • Loop variable i is local — it doesn't persist after the loop
  • A function definition doesn't run the code, calling it does
  • Array index starts at 0, not 1
  • Objects must be created with new before use (in Java)
  • State string comparison needs === not ==
