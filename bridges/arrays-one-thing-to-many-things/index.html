Arrays: One Thing to Many Things

How code moves from one named variable to a list — and a loop that visits every item without growing the drawing code.

One object before fifty.

Students understand one ball before they understand fifty. This bridge makes the shift explicit: the same properties still exist, but now they live in an array and a loop visits each one. The key moment is adding a new value to the array and watching the drawing code stay exactly the same.

  • Start with one visible object — name every property out loud.
  • Replace repeated variables (x1, x2, x3) with an indexed array.
  • Write a loop so one rule draws every item.
  • Push a new value to the array — notice the loop code didn't change.

Common misconception

"To draw five shapes, I copy the drawing code five times." — Let students try x1, x2, x3, x4, x5 first. The awkwardness creates the need. The moment they ask "what happens when I need twenty?" is when the array makes sense.

Before: repeated variables

three names, three edits 
let x1 = 40;
let x2 = 90;
let x3 = 140;

function draw() {
  background(246);
  circle(x1, 80, 24);
  circle(x2, 80, 24);
  circle(x3, 80, 24);

  x1 += 1;
  x2 += 1;
  x3 += 1;
}

This works, but the structure is fragile. A fourth circle means a fourth variable, a fourth draw line, and a fourth update line.

After: one array, one rule

many values, same loop 
let xs = [40, 90, 140];

function draw() {
  background(246);
  for (let i = 0; i < xs.length; i++) {
    circle(xs[i], 80, 24);
    xs[i] += 1;
  }
}

The amount of data can change without changing the algorithm. Add xs.push(190); the loop already knows how to visit it.

What students are really learning

An array is not just "several variables in brackets." It changes the shape of the problem. With separate names, the program asks the programmer to remember every object. With an array, the program asks for a rule that applies to each item. That is the move from manual drawing to algorithmic drawing.

The index is the bridge between the list and the canvas. xs[i] means "the x value for the item I am visiting right now." When students can point to the current item, predict the next index, and explain why the loop stops at i < xs.length, they have the mental model needed for arrays of objects, ArrayList traversal, and data-driven sketches.

Stable part

The drawing rule stays stable: draw a circle, move it, check the next item.

Changing part

The data changes: more positions, fewer positions, different starting values.

Payoff

The loop connects the stable rule to whatever data exists today.

Bridge moves

One thing

Draw one circle with x, y, and speed. Name every property out loud. Ask: "What changes if the sketch needs ten circles?"

Many values

Collect related values in one array. Print the array so students can see the list exist in memory — not just as code on screen.

One rule

Write a loop so every item follows the same update-and-draw rule. Push a new value to the array — the loop code stays the same.

Discussion question

If you push a new item to the array, what changes in the loop code?

Follow-up: what happens if xs has 3 items but ys has only 2?

Key vocabulary

array index .length push() for loop off-by-one

p5.js — one rule draws every item 
let xs = [40, 90, 140, 190];
let ys = [80, 60, 100, 75];

function draw() {
  background(246);
  for (let i = 0; i < xs.length; i++) {
    circle(xs[i], ys[i], 24);
    xs[i] += 1;          // same rule, every item
  }
  // Try: xs.push(230); in setup() — loop code unchanged
}

3-minute demo script

Step 1. Write let x1 = 40; let x2 = 90; let x3 = 140; and draw three circles by hand. Ask: "What happens when we need a fourth?" Let students feel the repetition build.

Step 2. Replace with let xs = [40, 90, 140]; and print(xs). Show the list in the console. Ask: "How do we get the first item? The last?"

Step 3. Write the for loop. Run it. Add a fourth value to the array in setup(). Run again — ask "what changed in the loop code?" (Nothing did.)

Watch for: students accessing arr[arr.length] — off by one, returns undefined. Print the value before using it so students can see undefined appear in the console.
