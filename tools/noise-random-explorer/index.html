Noise vs Random Explorer

One function produces chaos. The other produces landscape. Both look unpredictable — but only one you can walk through.

Noise Walker sketch All tools

Same idea, completely different feel.

random() picks any value with no memory of the last one — output is disconnected and jittery. noise(t) moves through a smooth continuous field — output flows. The key insight is that noise() needs a changing input: the same argument returns the same value every time.

  • Show jitter first — students find it harsh and uncontrollable.
  • noise() is the fix. But only if the input changes each frame.
  • Advance the input: t += 0.02 each frame.
  • Smaller increments = smoother output. Larger = more jitter.

Classroom flow

Jitter first

Show a dot at random(width) each frame. Students feel how abrasive it is. Ask: "What would make it calmer?"

Introduce noise(t)

Replace with noise(t) where t += 0.02 each frame. The dot now drifts. Ask: "What happens if we don't change t?"

Tune the increment

Use the slider — very slow vs fast. Ask: "What does the increment control?" Smooth randomness is a design parameter, not an accident.

Common mistake

Calling noise(0) every frame — the input never changes, so the output never changes. Always advance: noise(t) where t increments each frame.

Discussion question

If t += 0.02 gives smooth movement, what does t += 0.5 look like? Is there an increment that makes noise indistinguishable from random?

Extension: 2D noise

Switch to Terrain mode — values close in space are close in value. Compare to a grid of random() values (static snow).

p5.js — noise walk vs jitter 
let t = 0;

function draw() {
  background(246);

  // noise: smooth drift
  let nx = map(noise(t), 0, 1, 20, width - 20);
  fill('#d96a3d');
  circle(nx, height / 3, 20);

  // random: teleports every frame
  let rx = random(width);
  fill(100);
  circle(rx, (2 * height) / 3, 20);

  // advance the noise input — required
  t += 0.02;
}
