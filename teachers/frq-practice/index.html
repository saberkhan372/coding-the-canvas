FRQ Practice

The four AP CS A FRQ types — method writing, class design, array/ArrayList, and 2D array — each connected to the CS Canvas lesson where students first met that concept visually.

AP CS A coverage map 09 Objects lesson

Why visual context helps FRQs

The canvas makes the state visible.

FRQ questions often feel abstract because students can't see what the code is doing. A canvas sketch is the opposite: every variable has a visible location, every loop has a visible repetition, every list item has a visible position on screen. Use the sketches as FRQ setup context — then take the canvas away and ask students to write the method.

  • Method writing FRQ → functions/methods that update canvas objects
  • Class design FRQ → the Ball, Particle, or Tile class from §4
  • Array/ArrayList FRQ → the particle array or dynamic swarm from §4/§7
  • 2D Array FRQ → the pixel grid from §5 (image data)

FRQ type 1 — Method writing

Method writing FRQ type 1 · Part A

Canvas connection: Concept 07 Functions and Concept 09 Objects. Students who have written move() and draw() methods on a Ball class are directly prepared for this type.

// Given this partial class from the CS Canvas objects lesson: class Ball { float x, y, r, vx, vy; Ball(float x, float y) { ... } void draw() { ellipse(x, y, r*2, r*2); } // TODO: write the move() method. // It should update x and y by vx and vy. // If x goes out of bounds (0..width), reverse vx. // If y goes out of bounds (0..height), reverse vy. void move() { // your code here } }

FRQ skills practiced:

increment/decrement conditional boundary check negation of velocity this. reference

Practice set — progressively harder

Write a grow(float amount) method that increases r by amount, capped at 50.
→ arithmetic + conditional max
Write a boolean isOffscreen(int w, int h) method that returns true if the ball center is outside the canvas.
→ compound boolean expression
Write a float distanceTo(Ball other) method returning the Euclidean distance between centers.
→ Math.sqrt + parameter access
Connected lessons: 07 Functions · 09 Objects · 10 State Machines

FRQ type 2 — Class design

Class design FRQ type 2 · Writing a full class

Canvas connection: Concept 09 Objects is exactly this FRQ type. Students have already written a Ball class with fields, a constructor, and methods. The FRQ asks them to do that same thing for a different domain.

// Design a Tile class for a grid visualization sketch. // A Tile has: a column (int col), a row (int row), // a brightness value (float, 0.0 to 1.0), // and a boolean "active" flag. // // Write: the complete class declaration including // all fields, one constructor, and these methods: // - void draw() — draws the tile at (col*size, row*size) // - void darken(float amount) — decreases brightness by amount, min 0 // - boolean isActive() — returns the active flag // - void toggle() — flips the active flag
field declaration constructor assignment method signatures boolean toggle Math.max for clamping

Practice set

Design a Star class for a night-sky sketch. Fields: x, y, radius, twinkleSpeed. Methods: draw(), twinkle() that oscillates radius.
→ sin/cos for oscillation
Design a DataPoint class for a scatter plot. Fields: value (float), label (String), highlighted (boolean). Methods: draw(float scaleX, float scaleY), setHighlighted(boolean b).
→ parameter-scaled drawing
Connected lessons: 09 Objects · 07 Functions · 10 State Machines

FRQ type 3 — Array / ArrayList

Array & ArrayList FRQ type 3 · Traversal & manipulation

Canvas connection: Concept 08 Arrays (fixed-size traversal) and Concept 22 ArrayList in Action (dynamic add/remove). The particle swarm that grows and shrinks is the canonical ArrayList FRQ context.

// Given an ArrayList of Ball objects: // ArrayList<Ball> particles = new ArrayList<Ball>(); // Part A: Write addParticle(float x, float y) // that creates and adds a new Ball at (x, y). // Part B: Write removeSmall() // that removes all Balls with r < 5 from the list. // Must use correct iterator-safe traversal. // Part C: Write int countFast() // that returns how many Balls have speed > 3. // Assume Ball has getSpeed() method.
ArrayList.add() Iterator remove pattern for loop vs for-each accumulator count ConcurrentModificationException trap

Practice set

Write Ball findLargest(ArrayList<Ball> list) that returns the Ball with the greatest radius, or null if the list is empty.
→ running max + null guard
Write void keepTop(ArrayList<Ball> list, int n) that removes all but the n largest balls.
→ sort + subList.clear() pattern
Connected lessons: 08 Arrays · 22 ArrayList in Action · 09 Objects

FRQ type 4 — 2D Array

2D Array FRQ type 4 · The killer canvas demo

Canvas connection: Concepts 11, 13, and 15 — Pixels, Binary as Pixels, and Histograms. Image pixel data is a color[][] (or int[][]) array. Students who have read and written pixel loops are directly prepared for nested-loop FRQs.

// A grayscale image is represented as int[][] pixels // where pixels[r][c] is brightness 0..255. // Part A: Write int brightest(int[][] pixels) // returning the maximum brightness value in the image. // Part B: Write int[][] invert(int[][] pixels) // returning a new array where each value is 255 - original. // Part C: Write int[][] blur(int[][] pixels) // returning a new array where each pixel is the average // of itself and its four cardinal neighbors. // Pixels at the border keep their original value.
nested for loop row/column indexing boundary condition new array allocation accumulator average

Why this one matters

The 2D array FRQ is consistently the hardest for students who've only seen abstract grid examples. When students have literally moved through pixels[r][c] in a Processing sketch and watched the canvas change, "row" and "column" stop being abstract. The border-condition error (accessing pixels[-1][c]) is visible as a runtime crash in the sketch — students learn to guard against it naturally.

Connected lessons: 11 Pixels / Image Data · 13 Binary as Pixels · 15 Histograms & Sampling

FRQ timing practice

The AP CS A exam gives students about 25 minutes per FRQ. For each recipe above, run a timed practice: give students the setup code and prompt, 25 minutes, no notes. Debrief with the canvas visual before reviewing the solution.

Trace-first strategy

Before writing code, train students to trace: draw a small example by hand and trace through it mentally. For 2D array FRQs, this means drawing a 3×3 grid and labeling the expected output cell by cell. Students who trace first write fewer bugs.

Common FRQ mistakes

  • Missing return on non-void methods
  • Modifying the original array in "return new array" problems
  • Off-by-one in loop bounds (<= vs <)
  • Removing from ArrayList while iterating forward
  • Forgetting to check for empty list before returning
