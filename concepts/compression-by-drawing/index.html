Compression by Drawing

Compression replaces repeated data with shorter instructions. A picture can be redrawn from a recipe instead of stored pixel by pixel.

Try it in the Playground Section overview

Concept 14 / 22

The big idea

If a bitmap has a long run of repeated pixels, you do not need to write every pixel down. You can store the value and the count. That is the heart of run-length encoding: data becomes drawing instructions.

  • Identify repeated runs
  • Encode as value + count
  • Decode by drawing the run back out
  • Compare original length to compressed length
  • Name the tradeoff: compression works best when data has patterns

let runs = [
  ['white', 3], ['black', 5],
  ['white', 2], ['black', 2], ['white', 4],
  ['black', 8]
];

function setup() {
  createCanvas(400, 120);
  noLoop();
}

function draw() {
  let x = 0;
  let cell = 20;
  for (let [value, count] of runs) {
    fill(value === 'black' ? 28 : 246);
    for (let i = 0; i < count; i++) {
      rect(x * cell, 40, cell, cell);
      x++;
    }
  }
}

Processing / Java
String[] values = {"white", "black", "white", "black", "white"};
int[] counts = {3, 5, 2, 2, 4};

void setup() {
  size(400, 120);
  noLoop();
}

void draw() {
  int x = 0;
  int cell = 20;
  for (int r = 0; r < values.length; r++) {
    fill(values[r].equals("black") ? 28 : 246);
    for (int i = 0; i < counts[r]; i++) {
      rect(x * cell, 40, cell, cell);
      x++;
    }
  }
}

The canvas idea

Have students draw a stripe pattern, write the full pixel string, then write the compressed recipe. The saved characters become visible.

Patterns to notice

  • Run-length encoding
  • lossless compression
  • decode loop
  • file size estimate
  • patterns compress better than noise

Teacher notes

Do a bad example too: random pixels often get larger after RLE. That makes compression honest instead of magical.

Common misconception: Students often think compression always makes a file smaller. It only helps when the encoded pattern costs less than the original.
