World Coordinates: push() and pop()

translate() moves the origin. rotate() spins everything after it. push() saves the world. pop() restores it. Without pop(), transforms leak.

Every shape lives in a world. You can move the world.

Instead of calculating rotated positions by hand, you move the coordinate system to where you want to draw, draw at (0, 0), then restore the system. push() saves the current transform state. pop() restores it. They are always a pair.

  • translate(x, y) moves the origin — all shapes shift.
  • rotate(angle) spins the entire world from the current origin.
  • push() saves: origin position, rotation, fill, stroke.
  • pop() restores exactly what was saved — no math required.
  • Every push() must have a matching pop().

Common misconception

"push() and pop() are the same as array methods." — These have nothing to do with arrays. push() saves the current drawing state (origin, rotation, fill, stroke) onto an internal stack. pop() restores the most recently saved state. The name is from a stack data structure, not from Array.push().

Before: transform leak

the second shape inherits the moved world 
function draw() {
  background(246);

  translate(120, 80);
  rotate(frameCount * 0.02);
  rect(-30, -6, 60, 12);

  // also translated and rotated
  circle(30, 30, 20);
}

The circle is coded at (30, 30), but it is drawn inside the transformed coordinate system because nothing restored the original world first.

After: save and restore

the second shape gets the normal world back 
function draw() {
  background(246);

  push();
    translate(120, 80);
    rotate(frameCount * 0.02);
    rect(-30, -6, 60, 12);
  pop();

  circle(30, 30, 20);
}

push() takes a snapshot before the transform. pop() returns to that snapshot so later drawing is independent.

What students are really learning

Transforms do not move one rectangle. They move the coordinate system that future drawing commands use. That is why rect(0, 0, 40, 20) can appear at a translated origin, and why rotate() affects every shape drawn after it until the transform is restored.

In p5.js and Processing, the transform state is reset at the start of each new draw() frame. The bug is not that the canvas drifts forever from frame to frame. The bug is that one transformed object leaks into the next object in the same frame, same function, or same recursive call. push() and pop() create a local drawing context so each object can move its own world without surprising the rest of the sketch.

Save

push() remembers the current transform and style settings before a local drawing move.

Change

translate(), rotate(), fill(), and stroke() affect drawing commands that come after them.

Restore

pop() returns to the saved state so the next shape starts from the expected coordinate system.

Bridge moves

Translate, then draw

Call translate(100, 50) and draw a rect(0, 0, 40, 40). The rect appears at (100, 50) even though you coded (0, 0). Ask: "Where is the origin now?"

Without pop(), the leak

Don't use push()/pop(). Draw a second shape expecting it at (0, 0). It appears shifted or rotated because it inherits the transform from earlier in the same draw() pass.

Wrap and restore

Wrap the first shape in push()/pop(). The second shape returns to the original (0, 0). Ask: "What saved the world?" (push() did. pop() restored it.)

Discussion question

If you call translate(100, 0), draw a rectangle, and then draw a circle without pop(), which coordinate system does the circle use?

Follow-up: where should push() and pop() go if only the rectangle should be translated?

p5.js — push/pop keeps shapes independent 
function draw() {
  background(246);

  // shape 1: rotated arm at (120, 80)
  push();
    translate(120, 80);
    rotate(frameCount * 0.02);
    rect(-30, -6, 60, 12); // drawn around local (0,0)
  pop(); // origin restored to (0, 0)

  // shape 2: unaffected by the rotation above
  fill(217, 106, 61);
  circle(30, 30, 20);
}

3-minute demo script

Step 1. Draw a rect at (0, 0) with no translate. Run. Then add translate(100, 60) before the rect and run again. Ask: "Where is (0, 0) now? What moved — the shape, or the world?"

Step 2. Add a second circle(0, 0, 20) after the rect, no push/pop. Ask students to predict where it appears. Run. The circle is also at (100, 60) — the world moved for everything.

Step 3. Wrap the rect in push()/pop(). Run. Circle returns to (0, 0). Ask: "What did push() save? What did pop() restore?"

Watch for: Students expecting translate() to affect only the next shape. Say: "It changes the world for every drawing command after it until we restore the world." Then point out that p5.js resets transforms at the start of the next frame, so the leak is about order inside the current frame.
