Sketch Playground

A classroom workflow for remixing examples, testing small changes, and seeing code affect the canvas.

Edit, run, notice, remix.

The playground is the default habit for a visual CS lesson: start from working code, make one intentional change, run it, and explain what changed on the canvas.

  • Keep examples short enough to scan.
  • Change one variable or line at a time.
  • Use the canvas output as the first debugging signal.

Classroom flow

Start from a known-good sketch

Students should begin with code that already draws something visible.

Make one change

Change a number, color, condition, or loop bound and predict the result.

Run and explain

The canvas becomes evidence. Ask students to point to the line that caused the change.

Use in class

Open a concept page, copy a snippet, then run it in p5.js or CodePen from the export controls.

Debug habit

If nothing appears, check canvas size, background, fill, and whether draw/setup are running.

Portfolio habit

Save a screenshot plus the line that made the most important change.

starter remix prompt
Change exactly one thing:

1. Move the circle.
2. Change its color.
3. Add a second shape.
4. Explain which line caused the visible change.
