See it, say it, code it.

Students often write if (i % 2 === 0) without understanding why even-numbered positions get colored. This tool makes the rule visible: pick a divisor, watch which cells light up, count aloud. The pattern explains the code, not the reverse.

  • Say the rule in plain English before touching the code.
  • Change the divisor — predict first, then check.
  • Every even/odd pattern is just % 2. Every third is % 3.
  • Nested rules (i % 2 === 0 && j % 3 === 0) still follow the same logic.

Classroom flow

Pick a rule

Start with i % 2 === 0 — every even index. Ask students which circles will be colored before anything runs.

Count aloud

Go through i = 0, 1, 2, 3 … with students. Say the remainder at each step. The repetition is the lesson.

Change the divisor

Switch to % 3, then % 4. Ask "which cells are colored now?" before updating the grid.

Use in class

Start with even/odd (% 2) — every student can check the answer by counting. Only move to thirds when the pattern feels obvious.

Discussion question

If you change % 3 to % 4, how many fewer cells are colored in a row of 12? Answer without running the code first.

Extension

Nested rules: try i % 2 === 0 && j % 2 === 0. Draw the expected pattern on paper before switching to a 2D rule.

pattern rule — every third cell 
for (let i = 0; i < 8; i++) {
  let x = 40 + i * 30;

  // rule: color every third position
  if (i % 3 === 0) fill('#d96a3d');
  else noFill();

  circle(x, 100, 24);
}

// change 3 → 2 and predict before running
