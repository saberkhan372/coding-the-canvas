Create Performance Task Support

Every CS Canvas sketch can become a Create PT. Here are three starter recipes, the required artifacts, and a milestone timeline to keep students on track.

AP CSP coverage map Rubric guide

What the Create PT requires

A program with a list, a procedure, and an algorithm.

The College Board requires students to submit a program they wrote with specific features: at least one list (or collection), at least one student-developed procedure with a parameter, and an algorithm that includes sequencing, selection, and iteration. CS Canvas teaches all of these — the trick is intentionality.

  • Video: 1 minute of the program running
  • PDF: program code (entire file)
  • Written response: 3 prompts about list, procedure, and algorithm
  • Student-developed means: the student wrote it, not copy-pasted it

Three starter recipes — pick one

Recipe 1 List + procedure

Build a sketch that stores objects in an array and calls a method (procedure with a parameter) to draw or update each one. The for loop that iterates the array is your algorithm.

  • List: let particles = []
  • Procedure: drawParticle(p, color)
  • Algorithm: for loop + if for boundary check
Concepts: 08 Arrays · 07 Functions · 09 Objects
Recipe 2 Iteration + selection

A grid-based visualization where each cell is computed by a function that takes row and column as parameters, with conditional logic to determine what gets drawn.

  • List: let grid = [] 2D data
  • Procedure: drawCell(r, c, value)
  • Algorithm: nested loop + color selection by value
Concepts: 06 For Loops · 05 Conditionals · 15 Histograms
Recipe 3 Abstraction + algorithm

A state-machine game with three screens. Objects in an array, a student-written update procedure, and conditionals that check game state. The abstraction is the game object hiding its logic.

  • List: enemies[] or stars[]
  • Procedure: update(speed) on the class
  • Algorithm: state machine + array traversal
Concepts: 09 Objects · 10 State Machines · 08 Arrays

Milestone timeline — last 6 weeks

1
Choose a recipe + sketch a plan decision doc
Students pick one of the three recipes (or propose their own with teacher approval). They write 3 sentences: what the program does, what the list holds, and what the procedure computes. Teacher approves before any code is written.
2
Working prototype — list + basic loop code check
Students have a running sketch with the list and a loop over it. It doesn't have to look good — it has to prove the list and iteration are working. Teacher checks: is the list populated? is it iterated with a loop? is it a student-written loop, not a library call?
3
Add the procedure with a parameter code review
Students extract a block of repeated code into a named procedure with at least one parameter. Teacher checks: does the parameter actually change behavior? Is this student-written? (Library functions like circle() don't count.)
4
Record the video 1-min video
Screen recording showing input, the program running, and output. Students narrate or the program visually demonstrates both the list and the procedure in action. Common mistake: recording a static sketch — the program must do something while the video runs.
5
Draft written response 3 prompts
Students answer the three College Board prompts: (2a) describe the list and why it's needed; (2b) describe the procedure and how the parameter affects behavior; (2c) describe the algorithm that includes sequencing, selection, and iteration. Each answer is 200 words maximum.
6
Final submission submit
Export the full program as a PDF. Attach the 1-minute video. Submit written responses. Teacher does a final check: does the written response match the actual code? Does the video show the list and procedure in action? Common last-minute issue: code submitted doesn't match what was demoed.

Common pitfalls

  • Using a library function as the "procedure"
  • The list holds one item, never iterated
  • The video doesn't show the list or procedure in action
  • Written response describes a different program than the one submitted
  • Submitting code that doesn't run

The §4 connection

The §4 section checkpoint (particle system) is designed to be CPT-ready: it has an array of objects (the list), a class method with a parameter (the procedure), and a for loop with a conditional (the algorithm).

If students expand their §4 checkpoint instead of starting fresh, they usually finish Milestone 3 with time to spare.

Processing Java & CS A

AP CS A has no Create PT. If you teach both CSP and CS A sections, you can run the Create PT separately. The CS A parallel is the FRQ — see the FRQ Practice page for how the same sketches generate FRQ-aligned assessment.
