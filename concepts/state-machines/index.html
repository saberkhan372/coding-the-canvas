State Machines

One variable tracks which mode is active. draw() checks it every frame. Click a button — the state changes — and the entire screen changes with it.

Try it in the Playground §4 Section overview

Concept 10 / 22

The big idea

Every interactive program has modes: a title screen, a play screen, a pause screen, a game-over screen. A state machine tracks which mode is active using a single variable. draw() checks that variable and renders the right screen. Transitions happen when events change the state.

  • State variable: let state = "menu"
  • draw() branches on state — renders one screen at a time
  • Transitions: events change state value (click → "playing")
  • Each state can have its own logic in draw()
  • Common states: "menu", "playing", "paused", "gameover"
  • State diagrams: circles with arrows showing valid transitions

Code — a three-screen sketch

p5.js
let state = "menu";
let score = 0;

function setup() { createCanvas(400, 300); }

function draw() {
  if (state === "menu") {
    drawMenu();
  } else if (state === "playing") {
    drawGame();
  } else if (state === "gameover") {
    drawGameOver();
  }
}

function drawMenu() {
  background(40);
  fill(255);
  textSize(32); textAlign(CENTER);
  text("Click to Start", width/2, height/2);
}

function drawGame() {
  background(240);
  score++;  // game logic here
  text("Score: " + score, 20, 30);
  if (score > 300) state = "gameover";
}

function mousePressed() {
  if (state === "menu")     state = "playing";
  if (state === "gameover") { state = "menu"; score = 0; }
}
Canvas API
let state = 'menu';
const ctx = canvas.getContext('2d');

function loop() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  if (state === 'menu') {
    ctx.fillStyle = '#282828';
    ctx.fillRect(0, 0, canvas.width, canvas.height);
    ctx.fillStyle = 'white';
    ctx.font = '24px sans-serif';
    ctx.textAlign = 'center';
    ctx.fillText('Click to Start', canvas.width/2, canvas.height/2);
  } else if (state === 'playing') {
    // game rendering...
  }
  requestAnimationFrame(loop);
}

canvas.addEventListener('click', () => {
  if (state === 'menu') state = 'playing';
});
loop();
Processing / Java
String state = "menu";
int score = 0;

void setup() { size(400, 300); }

void draw() {
  if (state.equals("menu")) {
    background(40);
    fill(255);
    textSize(28);
    text("Click to Start", 120, 160);
  } else if (state.equals("playing")) {
    background(240);
    score++;
    if (score > 300) state = "gameover";
  }
}

void mousePressed() {
  if (state.equals("menu")) state = "playing";
}

The canvas idea

Ask: "how does a game know to show the title screen vs. the game screen?" Students often think it's complicated. Show them it's just one string variable and an if/else chain in draw().

Draw the state diagram on the board first. Every circle is a state, every arrow is a transition event. Then translate directly to code.

State diagram template

  • "menu" → click → "playing"
  • "playing" → score > limit → "gameover"
  • "playing" → keypress → "paused"
  • "paused" → keypress → "playing"
  • "gameover" → click → "menu"

Teacher notes

Timing: 2 periods. Pairs with Objects (09) as a capstone for §4.

Java gotcha: String comparison in Java requires .equals(), not ==. This is a great moment to introduce the difference between reference equality and value equality.

Checkpoint: Students build a sketch with at least 3 states (menu, play, gameover) that transitions correctly on user events.
