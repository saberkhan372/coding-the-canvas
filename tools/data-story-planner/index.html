Data Story Planner

Five questions that turn a dataset into drawing decisions — before a single line of code is written.

Data Self-Portrait sketch All tools

Plan the drawing before planning the code.

Students who jump straight to code make two decisions at once: what to show and how to show it. This planner separates them. Answer the five questions on paper first. By the time students open an editor, the hard design work is already done.

  • Name your data and its real-world range before mapping anything.
  • Choose the visual mark (bar height, circle size, color) deliberately.
  • Write the map() call on paper — then copy it into code.
  • Ask what the chart reveals that a table of numbers doesn't.

The five planning questions

1

What is your dataset?

Name the data and where it came from. A dataset without a source is just numbers.

Example: Hours of sleep for each day of the week. Collected from my own phone health app.
2

What is the real range of your values?

The minimum and maximum in the real world — not on the canvas. You need this to write your map() call.

Example: Minimum 4 hours, maximum 9 hours. Real range: 0 to 10 (or 4 to 9 — your choice).
3

What visual mark will carry the data?

Height? Width? Radius? Brightness? Color hue? Each encodes differently. Choose deliberately, not by default.

Example: Bar height. Taller bar = more sleep. Bars grow up from the bottom edge.
4

What are your canvas dimensions and output range?

Write the map() call before opening the editor. If you can write it on paper, you understand it.

Example: Canvas 500 × 300. Bar height: map(value, 0, 10, 0, 220). Bars drawn from y=260 upward.
5

What does this chart reveal that numbers alone don't?

This is the most important question. If the chart doesn't reveal anything new, the visual mark choice may be wrong.

Example: The Thursday dip is obvious at a glance. A table of numbers makes it easy to skip over.

Classroom flow

Paper first

Print the five questions as a half-sheet. Students answer in pencil before opening any editor. The planner should take 5–8 minutes.

Write the map() call

Question 4 forces students to write map(value, min, max, 0, height - 40) before seeing a canvas. If they can write it, they understand the scaling.

Compare with a partner

Swap planners. Can your partner read your plan and describe what the canvas will look like? If yes, the plan is complete. If not, revise before coding.

Use in class

Give students a shared dataset (class survey results, weather data) and run the planner together before anyone codes. Compare the different visual mark choices — height vs radius vs color.

The hardest question

Question 5 ("what does this reveal?") is where most students get stuck. That's the right place to get stuck — it means they're thinking about communication, not just code.

Extension

Run the planner twice with the same data but two different visual marks. Draw both charts and compare: which shows the story more clearly? Which hides something the other reveals?

p5.js — the map() call from the planner, in code 
// From the planner:
// Data range: 0 to 10 (hours of sleep)
// Canvas: 500 × 300, bars from bottom

let data = [7, 6, 8, 5, 7, 9, 6];

function draw() {
  background(246);
  for (let i = 0; i < data.length; i++) {
    // Question 4 answer, translated directly:
    let h = map(data[i], 0, 10, 0, 220);
    let x = 50 + i * 62;
    rect(x, 260 - h, 44, h);
  }
}
