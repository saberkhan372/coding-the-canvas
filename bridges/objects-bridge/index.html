Objects: Bundling Data and Behavior

When a thing needs more than one variable to describe it — and more than one function to update it — that's an object.

Parallel arrays break when the thing gets complicated.

Three dots: xs[3], ys[3], speeds[3]. Add color: now colors[3]. Add size: now sizes[3]. Add a second dot type: you need a second set of five arrays. The moment you want a thing with multiple properties that move together, reach for a class instead.

  • An object bundles its data (fields) and its actions (methods) in one place.
  • The constructor sets starting values: this.x = x.
  • update() changes the object's state. show() draws it.
  • Add a new property → change only the class, not the loop.
  • Forgetting new returns undefined, not an object.

Common misconception

"Objects are just a fancier way to group variables." — The data bundling is the smaller half. The bigger insight is behavior: a Dot knows how to update() and show() itself. The for loop stays unchanged whether you have 3 dots or 300, and adding a new property means changing the class — not the loop, not the draw function, not the array.

Bridge moves

Feel the parallel array pain

Start with xs[], ys[], speeds[]. Ask students to add a color property. They now need a fourth array, four pushes, and an updated loop. Let the friction build before offering the fix.

Bundle into a class

Write class Dot with a constructor, this.x, this.y, this.speed. Create one dot with new Dot(40, 80). Print it — students see all properties together in the console. Ask: "How would you add color now?" (One line in the constructor.)

Add behavior as methods

Add update() and show() methods. The for loop becomes d.update(); d.show(). Push a new Dot to the array — the loop code is unchanged. That's the payoff.

Discussion question

If xs has 3 values and ys has 3 values and you add a 4th dot, what is xs[3]? What happens in the draw loop at index 3 for ys?

Follow-up: with a class, can this mismatch happen? Why not?

Key vocabulary

class constructor this new method field instance

AP connection

AP CS A Unit 5 (Writing Classes) is tested in every exam. All four FRQ types involve writing or completing a class. The §4 particle system checkpoint maps directly to U5 + U6.

p5.js — parallel arrays → class with methods 
class Dot {
  constructor(x, y) {
    this.x = x;
    this.y = y;
    this.speed = random(1, 3);
    this.col = color(random(255), 100, 80);
  }

  update() {
    this.x = (this.x + this.speed) % width;
  }

  show() {
    fill(this.col);
    circle(this.x, this.y, 20);
  }
}

let dots = [];

function setup() {
  createCanvas(400, 200);
  for (let i = 0; i < 10; i++) {
    dots.push(new Dot(random(width), random(height)));
  }
}

function draw() {
  background(246);
  for (let d of dots) {
    d.update(); // same two lines for 10 or 1000 dots
    d.show();
  }
}

3-minute demo script

Step 1. Write let xs = [40, 120, 200] and the matching ys and speeds arrays. Draw 3 dots moving. Now say: "Add a color to each dot." Let students feel the awkwardness of a fourth parallel array.

Step 2. Write class Dot with a constructor and this.color. Create one: let d = new Dot(40, 80). Print d in the console — students see the whole thing at once.

Step 3. Add update() and show(). Move to an array of dots and a for-of loop. Push one more dot and run — ask "what changed in the loop?" (Nothing.)

Watch for: Students forgetting new — Dot(40, 80) without new returns undefined and the error message doesn't say why. Print the variable before using it so students see undefined in the console.
