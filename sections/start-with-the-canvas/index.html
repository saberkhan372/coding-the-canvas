What this section covers

Students start with a blank rectangle and learn that every pixel has an address. The canvas coordinate system (origin top-left, y-down) is the first "gotcha" — and the first productive misconception to resolve. By the end of §1 students can write a sketch that places shapes anywhere on screen with intentional color.

  • Pixel addresses: every point has an (x, y) pair
  • Origin top-left, y increases downward
  • Canvas size vs. shape size vocabulary
  • fill, stroke, RGB color model
  • First complete sketch: intentional composition

Teacher framing

Prerequisites: None — this is the true starting point. Students who have never typed code can enter here.

Discussion move: Ask "where is the top-left corner of your phone screen?" before touching code. Students almost always place it wrong — that surprise is the hook.

Checkpoint: Students can place three shapes of their choosing at exact pixel positions and explain why y increases downward.

Learner framing

Think of the canvas as a grid of tiny lights. Every light has a column number (x) and a row number (y). Your code is the instruction sheet that tells each light what color to glow.

By the end of this section you'll write a program that draws something — really draws it, not just prints text — and you'll understand exactly why every number in that program means what it means.

Common misconceptions

  • y=0 is at the top, not the bottom
  • width/height of a shape ≠ its position
  • stroke() sets the border color, not text
  • RGB values go 0–255, not 0–100
